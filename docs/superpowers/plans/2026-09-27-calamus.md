# Calamus Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the `journaling/` skill pair into one Agent Skills–compliant skill, `calamus`, with a schema-driven journal writer/reader and a host-neutral, model-agnostic hook engine.

**Architecture:** `skills/calamus/` is the distributable. A single JSON schema drives validation, rendering (md/xml/jsonl), parsing, prompt shape blocks, and generated reference docs (Python 3 stdlib only). A bash entry point (`scripts/hook.sh`) normalizes host payloads, gates, extracts a bounded transcript window, calls a pluggable backend under a portable timeout, validates the JSON reply, and appends through the same Python writer. Every hook path exits 0 and prints nothing.

**Tech Stack:** bash (must run on macOS `/bin/bash` 3.2: no associative arrays, no `mapfile`, no `${var,,}`), Python ≥ 3.9 stdlib, `git`. No third-party packages.

**Spec:** `docs/superpowers/specs/2026-09-26-calamus-design.md` (amended 2026-09-27, commit `c1a23f9`).

## Global Constraints

- Hooks exit 0 on every path and write nothing to stdout (spec 4.2 step 11).
- Journals are append-only; no code path truncates or rewrites a journal file.
- Model strings appear only in `skills/calamus/assets/calamus.env`: `CALAMUS_CLAUDE_MODEL=claude-haiku-4-5`, `CALAMUS_CODEX_MODEL=gpt-5.4-mini`, `CALAMUS_CURSOR_MODEL=` (empty).
- Config files are parsed as data (`CALAMUS_[A-Z0-9_]+=value` lines only), never sourced; `CALAMUS_LLM_CMD` and `CALAMUS_*_BIN` are ignored in the project-level file.
- Journals never contain an absolute local path.
- `SKILL.md` ≤ 150 lines; each reference ≤ 300 lines; `description` ≤ 1024 chars; `name` = directory name.
- Defaults (spec 4.4): `CALAMUS_BACKEND=auto`, `CALAMUS_LEVEL1_GATE=sampled`, `CALAMUS_LEVEL1_SAMPLE=4`, `CALAMUS_BACKEND_TIMEOUT=25`, `CALAMUS_TAIL_SWEEP=28000`, `CALAMUS_TAIL_SNAPSHOT=20000`, `CALAMUS_RAW_WINDOW=262144`, `CALAMUS_EXTRACT=on`, `CALAMUS_MIN_BYTES_SWEEP=800`, `CALAMUS_MIN_BYTES_SNAPSHOT=500`, `CALAMUS_MIN_TEXT=8000`, `CALAMUS_DEDUPE_SECS=30`, `CALAMUS_SESSION_END_MODE=auto`, `CALAMUS_FORMAT=md`, `CALAMUS_EVAL_BACKEND=claude`.
- Commits: conventional, no AI attribution trailers (owner's global rule overrides the harness default). Local only; no push.

## Review Focus

1. **Journal written by an older Calamus/journaling version or by hand** (free-form Markdown, headings without an id comment, EVAL-FAIL blockquotes): parse must not crash, must yield tag/date/title, and appends must not alter prior bytes. → Task 3 tests against `docs/dev_journal.md` and `docs/product_insights.md`.
2. **Hostile or odd text in model output** (`-->` inside a title, `]]>`, `<`, `&`, backticks, unicode, CRLF, 50 KB fields): md comments must not be closed early, XML must stay parseable. → Task 2 escaping tests (`-->` is rewritten to `--&gt;` inside md comments; titles are whitespace-normalized).
3. **Session ids with path characters** (`../x`, `a/b`, spaces) used in state filenames and markers. → Task 6 sanitizes to `[A-Za-z0-9._-]`, max 64 chars; test with `../../etc`.
4. **Journal in a non-git directory, or `docs/` not writable**: hook exits 0, logs, no stdout. → Task 8 test with `chmod -w docs`.
5. **A backend that prints to stderr, hangs, or ignores SIGTERM**: timeout kills the whole process group; hook still exits 0 within budget. → Task 5 test with a `trap '' TERM; sleep 60` backend.

### Task 2: Schema, validation, rendering

**Files:** `assets/schema/entry.schema.json`, `scripts/lib/schema.py`, `scripts/lib/render.py`, `tests/test_schema.py`, `tests/fixtures/golden/*.md|xml|jsonl`.

**Interfaces (produced):**
- `schema.load() -> dict` (path resolved relative to the lib file).
- `schema.normalize(rec: dict) -> dict` collapse runs of whitespace to one space in every text/list-item/title (not `code`); strip; CRLF→LF in code.
- `schema.validate(rec: dict) -> list[str]` field errors, `[]` if valid. Record kinds: `{"record":"entry","journal":"engineering"|"product","variant":..., "tag","date","title", <fields>, "crosslog"?: {...}}`, `{"record":"marker","kind":..., ...}`.
- `schema.content_hash(rec) -> str` sha256 hex of `json.dumps(rec minus id, sort_keys=True, ensure_ascii=False)`.
- `schema.make_id(rec, now: datetime) -> str` `YYYYMMDD-HHMM-<hash[:4]>`.
- `render.render(rec, fmt: "md"|"xml"|"jsonl", ext: str) -> str` (one record, trailing newline included); `render.header(journal, fmt) -> str`.

**Schema shape** (JSON): `{"version":1, "journals":{engineering:{tags:[CP-*], header_md:"...", files:{md,xml,jsonl}}, product:{...}}, "variants":{"engineering.lightweight":{"heading":"### [{tag}] | {date}: {title}","fields":[...]}, ...}, "markers":{...}}`. Each field: `{"key","label","shape":"text|list|enum|code|group|evidence","layout":"inline|bullets|group|code","required":bool,"enum":[...]?, "empty_md":"None identified."?, "sub":[fields]?, "xml":"element"}`.

Variants and md labels (copied from today's schemas):
- `engineering.lightweight`: Summary (text, inline) · Files/Modules Affected (list, inline, backticked, empty → `None identified.`) · Key Trade-off (text) · Evidence (evidence: `{status: verified|unverified, text}`; md `Not yet verified.` prefix when unverified) · Follow-ups (list, inline joined by `; `, empty → `None identified.`).
- `engineering.full`: The Context & Problem (bullets) · Design Decisions & Trade-offs (group: Choice, Alternatives Considered, Why) · The Pivot/Revision (bullets) · Implementation Notes (group: Files/Modules Affected inline list, Core Pattern Introduced) · Verification & Evidence (bullets) · Documentation & References Utilized (bullets, optional, omitted when empty) · Code Snapshot/Diff Concept (code, optional) · Cross-Log (bullets, empty → `None.`) · Open Questions / Follow-ups (bullets, empty → `None identified.`).
- `engineering.snapshot` (tag fixed `CP-COMPACT-SNAPSHOT`, title prefixed `Pre-compaction state — `): Summary · Files in progress (inline list) · Decisions made this context window (bullets, max 3) · Immediate next step (text) · Open questions (bullets).
- `product.lightweight`: Observation (bullets) · Why It Matters (bullets) · Evidence (group: Source text, Strength enum Strong/Medium/Weak) · Hypothesis / Next Step (bullets).
- `product.full`: all sections of today's Full schema; enums for Journey Stage, Strength, Primary Risk, Reach/Impact/Effort (Low/Medium/High/Unknown), Confidence (Low/Medium/High).
- Markers: `session{when,session,event}`, `compact{when,session}`, `resume{when,session,snapshot?}`, `pending{date,session,host,event}`, `resolved{date,session,entry}`, `eval-fail{backend,model,reason}`.

md entry layout: heading, blank, `<!-- calamus id:<id> schema:1 variant:<variant> -->`, blank, fields separated by one blank line, optional crosslog blockquote, blank, `---`, blank. Inline-list items rendered `` `item` `` for files, plain for follow-ups; validator rejects a list item containing the join separator or a backtick (files) with message `"<field>: item contains '<sep>'; split it into separate items"`. md comment text escapes `-->` as `--&gt;`.

- [ ] Write `tests/test_schema.py`: (a) golden: a fixed engineering.lightweight record renders byte-equal to `tests/fixtures/golden/eng-lightweight.md` (hand-written to today's schema plus the id comment line); (b) round trip render→parse (Task 3's parser, so this test lands in Task 3) — here: render all three formats for one record of every variant and marker without error; (c) XML output wrapped in `<j>…</j>` parses with `xml.etree`; every JSONL line `json.loads`; (d) validator rejects missing required field, tag `CP-NOPE`, strength `Maybe`, backtick in a files item; (e) text with `<`, `&`, `]]>`, `"`, `-->`, unicode survives XML/JSONL; `-->` never appears inside an md comment.
- [ ] Run → FAIL (modules missing). Implement schema JSON, `schema.py`, `render.py` (XML via `xml.sax.saxutils.escape`/`quoteattr`; code in CDATA with `]]>` split as `]]]]><![CDATA[>`). Run → PASS. Commit `feat(calamus): add entry schema, validator, and renderers`.

### Task 3: Parser and the single writer

**Files:** `scripts/lib/records.py`, `scripts/lib/journal.py`, `tests/test_records.py`.

**Interfaces:**
- `records.parse(path) -> list[dict]` dispatch by extension. md: split on `^### \[` headings and marker comment lines; heading regex `^### \[([A-Z-]+)\] \| (\d{4}-\d{2}-\d{2}): (.*)$`; id from comment or derived `YYYYMMDD-0000-<hash4>`; labels matched per variant (variant from comment, else best label match); unmatched text → `body`; entries parsed without a variant comment get `"legacy": true`. xml: wrap in root, ElementTree. jsonl: per line.
- `journal.resolve(root, journal, fmt_env) -> (path, fmt)` spec 4.8 detection (existing extension wins; multiple → `CALAMUS_FORMAT` else md + warning on stderr).
- `journal.append_records(root, journal, recs, fmt_env=None) -> list[str]` validates all first (raises `ValueError(errors)` before writing anything), refuses a duplicate content hash or id already in the journal, creates the file with `render.header` if absent, appends with `open(path, "a")` in one write, returns ids. Uses `fcntl.flock` on the file.

- [ ] Tests: round trip for every variant/marker in all three formats (render→parse equals normalized input); parse `docs/dev_journal.md` and `docs/product_insights.md` → every entry has tag/date/title, count equals `grep -c '^### \['`; append to a copy of `docs/dev_journal.md` leaves the original bytes as an exact prefix; duplicate refused; invalid batch writes nothing; format detection with `.md` + `.xml` present.
- [ ] Run → FAIL; implement; run → PASS. Commit `feat(calamus): add journal parser and append-only writer`.
